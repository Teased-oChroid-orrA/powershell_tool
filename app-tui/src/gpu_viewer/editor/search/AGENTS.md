# gpu_viewer/editor/search/ - the Search workbench in the native window

> TL;DR: `SearchSession` is an `Authoring` over the terminal toolbox's own `SearchToolState` (run, index, report, settings, recents, presets). It is a bench without a 3D model: `Authoring::document()` returns a page (search bar, live progress, results table, highlighted matches) that `gui/document.rs` draws where a model would be. No searching, matching or extraction lives here.

## Purpose
Owns: the window front end of Search (page, tree, popovers, value cards, menus), its own tokio runtime and event channel, the results view order (filter / sort / selection), the native folder picker call.
Does not own: running a search, the index, reports or settings persistence (`toolboxes/search`: `run_or_notify`, `apply_event`, `exec::execute`, `persistence`), the settings table (`toolboxes/search/settings_view.rs::settings()`), the page's drawing (`gpu_viewer/gui/document.rs`).

## Contracts
- **One run path for both heads.** Events go through `toolboxes::search::apply_event`, effects through `toolboxes::search::exec::execute`, a run starts through `run_or_notify`. The terminal's `app.rs` / `main.rs` call the same functions; never re-implement a reducer arm or an effect here. Per-file in-flight status (root `CLAUDE.md` hard requirement) is drawn from `run.in_flight_files` every poll.
- **Settings are the terminal's.** `SearchToolState::default()` loads `settings-tui.json`; option rows are `settings_view::settings()` rows (label, hint, parse, kind), so a setting added there appears here. Settings are written on every change and on drop. Tests use `SearchSession::in_memory()`: no load, no save, no HTML report, and a folder picker that answers "cancelled" (never a real dialog). The report is off because an empty output folder means the working folder: a test run used to leave `app-tui/search-report.html`, which failed `scripts/qualify.py`'s unchanged-source check on every OS. A test that checks the report sets `export_html` and its own output folder.
- **Exclude is a row of the page, not an option.** The `Exclude` chip (`SearchAct::ToggleExclude`) shows a second bar row (`Document::extra_inputs`, `INPUT_EXCLUDE`) with its own guide (`exclude_help`) and a segmented scope choice (`DocInput::choices`: Whole file / Matching lines). Exclude filters and Exclude scope are never in the Options popover. Hiding the row does not turn exclusion off: while terms are set, the chip stays lit and names them, so an applied exclusion is always visible. The row opens shown when the saved settings (or an applied preset) exclude something.
- **The cards move and resize.** Each card's grip (dots + title) drags it to the nearest side of the room (left / right / top / bottom; the drop is previewed), the other card takes the rest; the splitter between them sets the shares (double-click: default). The result is `Command::SetPageLayout`, kept in `display.json` (`DisplaySettings::page_layout`). A narrow room still stacks and a short one still shows the list alone, whatever the stored layout says (`page_layout::split`).
- **No docks.** A page bench gets no tool pill, no step strip and no inspector (`Gui::build` checks `Authoring::has_document`); options live in bar popovers (`Document::panels`: Options, Index, Ask, Report), the file-type picker is a modal (`Document::modal`), the Find syntax guide is a popover behind the label link (`DocInput::help`; an example click fills Find). The window skips scene drawing, orbit / zoom / pick and viewer keys in page mode (`Viewer::page_mode`).
- **Both folders are an input plus Browse.** The folder to search (bar) and the output folder (Report popover, `DocPanel::inputs`, `INPUT_OUTPUT`) are typed or chosen with the same picker (`SearchSession::pick`); the output picker starts in the output folder, else the searched one. Output folder is never a settings row or value card (`Edit(14)` and the ribbon open the picker). Empty output folder: the report lands in the working folder, Export matches beside each file.
- **Browse is the OS folder picker** (`rfd`, feature `gpu-viewer`): modal, on the window thread (macOS requires it). It blocks the event loop while open; the background search keeps running and its events are folded in on the next poll.
- The results table shows files with a hit, in found order until a column is clicked; `selected` is an index into `run.results` (append-only during a run), so selection survives new results. The detail shows the full extracted document with matches highlighted. It uses the result's cached lines when complete; otherwise it reloads and extracts the file in the background. A changed or unreadable file shows an error. Export matches writes the recorded hits.
- The document text is selectable; right-click opens Copy selection, without line numbers. The Open report button appears after an HTML report is written; the report never opens automatically.
- Both guides must stay true to the parser: `tests::every_example_of_the_exclude_guide_is_a_valid_exclusion` checks the Exclude guide; `tests::every_example_of_the_find_guide_parses_the_way_the_guide_says` parses every example and checks the tag semantics it describes. Change the guide and the parser together.

## Pitfalls
- `Authoring::document()` is rebuilt every frame, but its result rows are cached across unchanged frames. Run start, result count, filter, sort, selection and root path invalidate the cache. The table body is virtualised (`ScrollArea::show_rows`); large runs still clone cached rows each frame.
- Strings from the terminal toolbox may carry glyphs the window font lacks (`⚠`, `…`); pass them through `view::plain`.
- A short window drops the stacked detail (both need `MIN_STACKED`) and the figure tiles; this is deliberate, not a missing feature.
- Natural-language Find (`nl.rs`, feature `nl-find`, rule-based: `search_core::nl_rules`, no model) owns its state in `NlFind`; edits to the sentence call `reset`, which bumps a generation so stale search events are ignored. Understanding a sentence is synchronous; only the Find step runs on a blocking thread. Conditions are `DocPanel::chips` (pills), the Find button and cited results are the `search-nl` card. Design and evidence: `docs/search-natural-language-find.md`.
- **Ask is its own panel (feature `semantic-search`), not part of Index.** `view::ask_items` builds the conversation as `DockItem::Asked` (question bubble), `DockItem::Reply` (a quoted line plus its source) and `DockItem::Chips` (Look in: Search help / My files, and example questions); `panel_popover` draws the "Ask" panel as a page, not collapsible cards. Two places are searched per question part: `help.rs` ranks the unchanged lines of `help.txt` (embedded once in a `LineIndex`; a best line under `MIN_SIMILARITY` 0.30 means "not covered"), and the indexed folder via `file_evidence`. Nothing is generated. `help.txt` must stay true of the app: sections are `## Title`, one self-contained fact per line, `# src:` comments are ignored; `help_questions.tsv` holds the retrieval evaluation questions (top-1 section 90 percent, off-topic questions fall under 0.30). Questions about the app work with no folder or index. Change a feature the help describes and its help line together.
- **Scores and notes in the detail header are structured, not a run-on subtitle.** `DocDetail.signals` (`DocSignal`: label, 0..1 fraction, tooltip hint, one `primary`) draws labelled meters under the subtitle (`Gui::signal_meters` in `gui/document.rs`); `DocDetail.notes` draws quiet pills (`note_pills`) for facts such as "PDF text may be misread" or entity suggestions. Every ML number shown to the user should be a percentage with a plain-language hint; do not print raw cosine or three-decimal scores, and do not hard-code a model name in user text.
- **Refine results is opt-in and needs a model that is not shipped (`refine.rs`, feature `semantic-search`).** A "Refine results" row under the fast semantic hits starts `SearchAct::RefineResults`: on a blocking thread it re-runs the semantic search for the top 30 (`rank_fusion::REFINE_TOP`), scores each excerpt with bge-small (`search_core::second_model`, CLS pooling, query prefix "Represent this sentence for searching relevant passages: "), fuses the two rankings with reciprocal-rank fusion k=60 (`search_core::rank_fusion::fuse_top`, the `rerank-rrf` variant of `docs/search-benchmarks.md`), and the list is shown in that order (`evidence::select_ordered`, no similarity re-sort); the "% similar" figure stays the fast model's. Never automatic; progress is `Refining results: n of 30 passages read…` in the status line via `RefineEvent`. The model folder (`model.onnx` + `tokenizer.json`) is the first of: env `TOOLBENCH_RERANK_MODEL`, `rerank-model/` beside the exe, `<app data>/fea-editor/rerank-model/` (`resolve_model_dir`); none found: the status line names the folder. The loaded model is cached for the process (`Embedder::new` leaks the bytes). Real-model tests are `#[ignore]`d: `TOOLBENCH_RERANK_MODEL=<dir> cargo test -p app-tui refine -- --ignored`. Cost measured in the benchmark: seconds per query on a laptop CPU.
