# Issue 46 — Phase 90: curved boundaries in metric refinement and the AMR integration (#58)

Two of the three remaining #58 gaps (curved boundaries, AMR convergence integration).

**Curved boundaries.** `metric_refine::refine_projected(top, field, bounds, options, project)`: the vertex inserted on a *boundary* edge is moved by the caller's `project` (onto the true surface) when every tetrahedron around the edge, both halves, stays positively oriented with it (exact `orientation` test), and stays at the chord midpoint otherwise; interior edges are untouched. Input vertices are not moved by the insertion; the surface stays piecewise flat between vertices, so volume and area converge to the curved body's instead of being preserved (`refine` is unchanged: `refine_impl` with no projection). Test (unit sphere from the signed-distance mesher, isotropic target 0.3): the chord refinement keeps the start's volume 3.850 (exact 4.189, error 8.1 %); with projection 4.101 (error 2.1 %), all 192 inserted boundary vertices on the sphere to 1e-9, worst cell 0.545 against 0.520. A finer run (target 0.14, 18k cells): chords 4.066, projected 4.170 (error 3.0 % to 0.46 %), 840 of 840 inserted vertices on the sphere, worst cell 0.31 against 0.37.

**AMR integration.** `tests/amr_in_place.rs`: the controller (`run_amr`) with the in-place refinement as its mesher on the thick-walled quarter cylinder of `tests/tetmesh.rs` (Tet4, radial projection onto the bore and the outer wall, named outward faces rebuilt from the topology, pressure on the bore): the controller's `AdaptSize` becomes an isotropic metric, the previous topology is refined rather than regenerated, the physics estimator and the compliance goal run unchanged on the new meshes. Fast test (debug, 2 s, one adaptation): physics error 0.232 to 0.179, rms radial error against the Lame solution 6.2e-2 to 3.5e-2, the 6 inserted bore vertices on the bore. Study (`--ignored`, release, two adaptations to 10191 elements): physics error 0.232, 0.083, 0.064; rms radial error 6.2e-2 to **5.6e-3** (11x). 

Honest findings: (1) the signed-distance start mesh is itself at a scaled Jacobian of 0.032, so the controller's default floor of 0.1 can never be met by refining it in place; the run uses 0.03 ("not worse than the start"), a stated acceptance choice, not a relaxed numerical tolerance. (2) With the default smoothing, original vertices move (interior ones, and boundary ones that slide on a planar end face): the integration keeps vertex identity only with smoothing off, which then leaves the quality below even that floor; so the "every vertex survives exactly" property is not claimed. (3) The two-adaptation study takes about six minutes in release: the refinement loop (batched terminal-edge splits with metric flips and smoothing, `BTreeMap` rings rebuilt each pass) is the cost; a faster loop is needed before this is a production mesher. (4) The estimators used the recovery-based DWR fallback on tetrahedra (the enriched dual is 2D only).

Limits: one body; Tet4 only (no Tet10 midside projection); the projection is the caller's; flat-boundary flips do nothing on curved patches; CAD-constrained feature-preserving operations remain open; no Windows or hosted-CI evidence.
