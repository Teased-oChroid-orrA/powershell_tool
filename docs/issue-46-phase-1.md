# Issue 46 — Phase 1: audited migration boundary and verified mesh foundations

This is an implemented foundation milestone on `feature/native-cad-advanced-meshing`, not completion of the full epic or permission to merge/retire OCCT. The source qualification revision is `26775143208bde11518e6234757a7f4b62721d5b`. Read [the Phase 0 audit](issue-46-phase-0-audit.md) and [execution order](issue-46-execution-plan.md).

## Delivered code

- **CAD isolation (#48):** common profile/boolean/face types and an owned `cad::Brep` handle in `solid-kernel/src/cad.rs`; production `fea-problem` calls this boundary. Concrete cadrum objects stay inside the OCCT adapter. Old `occt` type exports remain compatible. Operation availability is explicit, and IGES/healing/persistent topology are not advertised. The neutral boundary currently dispatches only the existing OCCT adapter; it is not a native CAD replacement.
- **Predicates/topology (#49):** exact-sign orient3d/insphere using the already-locked `robust` dependency; explicit supported arithmetic envelope; positive cell orientation, reciprocal neighbours, duplicate/non-manifold rejection, immutable connectivity and atomic interior-cavity replacement preserving the external oriented boundary. Local topology checks do not certify arbitrary geometric nonintersection.
- **Reference 3D core (#49):** bounded deterministic point-set Delaunay insertion with explicit visible-hull handling, progress/cancellation, retained-point and convex-boundary checks. A finite-superstructure defect found by the 100-point benchmark was corrected by eliminating supervertices, not increasing padding or weakening volume tolerance. The regression checks the analytic unit-cube volume and empty circumspheres.
- **Solver bridge/quality (#53):** Tet4 conversion uses existing quality/conformity gates, rejects slivers/unused points and passes a closed-form tension patch. It has a generic boundary tag, not recovered CAD face identities. No sliver-removal optimizer or general PLC recovery is claimed.
- **Compatibility registry (#64):** deterministic capability/geometry/formulation/element/budget checks with stable reason codes; unsupported native-constrained/general-hybrid/curved-CAD combinations remain rejected. The audited initial slice is linear elastic; other formulation combinations are explicitly unaudited. Fixed invalid choices fail instead of silently switching physics. The simple first-compatible policy is not the full autotuner.
- **Verified telemetry (#50):** opt-in benchmark pipeline using the existing unmodified independent template references. A private, non-deserializable proof is created only after solving and passing independent accuracy/quality/equilibrium checks. Versioned local-first JSONL data are bounded, deduplicated by measurement (independent repeated trials survive), corruption-tolerant and exportable/clearable. Reloaded evidence is quarantined, not automatically trusted for learning. This pure-data library does not do application file I/O or enable automatic telemetry. Unknown peak memory is null, not inferred from factor storage. The example collector runs one explicitly selected benchmark, stores no CAD geometry and reports an exact caller-supplied source revision.

The reference point-set core **does not recover constrained segments/facets, cavities, CAD boundaries or material interfaces**. It is not offered in the application strategy registry. Production geometry and solver paths still use the existing verified meshers.

## Verification and failures

[Machine-readable verification](issue-46-phase-1-verification.json) records commands/revisions and current hosted outcome. The clean Linux foundations scope passed **53 meshing unit checks and five derivative benchmark/accuracy checks**, with matching clean start/end revision and `source_changed: false`. Two meshing tests were intentionally ignored in that regular command; the new reference scaling measurement was run explicitly and passed. Other ignored soaks are not claimed as passed.

The same clean source also passed **14 solid-kernel checks**, **45 problem-layer unit/solid/problem/units checks**, application lib/tests compilation with CAD, and the default CAD-feature-off compile. The three opt-in pilot collectors passed their independent references. The single targeted Windows job [38896885191](https://github.com/Teased-oChroid-orrA/powershell_tool/actions/runs/38896885191) **passed**; it did not rerun the full workspace or establish Windows CAD/hardware graphics support.

Reference scaling on this shared cloud machine (kernel dev/test profile): 20 points → 74 cells in 0.0011 s; 100 → 566 in 0.049 s; 256 → 1,564 in 0.310 s. Every run retained the analytic unit-cube volume within the unchanged 1e-12 criterion. This rebuilding implementation is a correctness reference, not a production throughput or scaling claim; peak memory for it was not measured.

Earlier development checks passed while follow-up edits were occurring; those are not represented as frozen-head qualification. `scripts/qualify.py` now records end revision/dirty state and rejects a passing qualification when source changes. An isolated simulation with a fake Cargo process verified both the unchanged-source success and changed-source failure paths; it is reporting-harness evidence, not numerical test evidence.

The previous reliability hosted run passed Linux/macOS but failed Windows in `derivative_bench`: measured four-lane time 43,591 ns versus eight-lane 41,462 ns violated a timing-order assertion. The fix preserves timing observations and verifies every lane against the closed form, direct/adjoint sensitivities against one another, matrix-free products against assembly, and existing storage/accuracy invariants. No numerical tolerance was relaxed. A single Windows-only foundations job was dispatched for this specific cross-platform regression; the full three-platform matrix was not rerun.

## Native CAD candidate research (#47/#51)

Truck upstream revision `88ed005249e5e3a6b07f62425399435905cd3ab6` was cloned and built outside the application checkout. Its generated lockfile SHA-256 is `890a80bfec10ea47f91637005e382a2d3b27871f492bea2968ead9b445a110d0`; no dependency or lockfile was added to this application. The application retains OCCT notices/licensing.

The upstream `step-to-mesh` example exceeded a 4 GiB RSS budget on the actual bracket before producing output (observed high-water 4,256,820 KiB; approximately 185 s at stop). A separate single-pass 0.1 mm probe avoided its preliminary 0.01 mm bounds tessellation, asserted all 38 native faces were retained and required every meshed face to exist. It still exceeded the same budget (4,221,236 KiB at 106.8 s) before producing a mesh. These results apply to this revision, fixture, driver and budget; they do not prove every Truck workflow fails. A single-thread repeat stayed below the memory cap (3,956,068 KiB high-water) but exhausted the 300-second wall budget without producing a mesh. Reducing parallelism therefore did not qualify the workflow. These are bounded probe outcomes, not proof that the entire library is unusable.

Source inspection also found converter paths that filter failed faces/boundaries. A production adapter must detect incomplete entity/loop coverage, validate topology/geometry/units/transforms and provide structured failures; successful parsing or a plausible preview does not meet #51. Current research does not qualify Truck as the production replacement. Existing ADR-019 boolean failures remain additional evidence until requalified.

## Remaining work and handoff

The full epic remains open. Next engineering gates are native B-Rep entity/trim/topology/units/assembly validation and a CAD-conforming, constrained volume mesher, followed by quality/sliver elimination, high-order/hybrid/metric adaptation and later motion/ALE. Efficient point location, geometric intersections, general facet recovery and production mesh-quality optimization are not supplied by the reference core. The early telemetry/registry slice is not a representative performance dataset or learned selector; learning remains deferred.

Retain the working OCCT adapter. Do not substitute the point-set hull mesher for a real CAD volume or bypass compatibility/geometry/accuracy gates. Future feature merges and final OCCT retirement still require their stated approval. Use the current issue comments and verification record for hosted status; historical initialization/pending notes above are snapshots, not current check outcomes.
