# Issue 46 — Phase 85: feature snapping ignored a violated face once any other face was close (#55)

Root cause of the off-surface vertices diagnosed in Phase 84 (which attributed them to the quality guard; that was wrong for the deepest ones). `tetmesh::snap_to_features` collected the faces within `edge_reach` (half the local edge length) and only fell back to the nearest face within `reach` when that set was **empty**. A boundary vertex lying on the z = 0 end plane (distance 0, so in the set) and 5 % of the local size *inside the bore* (distance 0.055 against an edge reach of 0.042) therefore projected onto the end plane alone: its target equalled its position, it was skipped as "no move", and it never reached the bore. Instrumented run (h = 0.14, 0.28): 4 + 8 vertices with target == position at sdf 0.111 and 0.055, every pass of every round. The Phase 84 snap-budget and edge-reach sweeps could not have fixed it (more passes repeat the no-move; a larger edge reach pulls vertices that are inside a face onto it too, which is why it made things worse).

Fix (`fea-core/src/tetmesh.rs`): a face the point lies **outside** of (positive distance) and within `reach` is always active, in addition to the faces within `edge_reach`. A point on the edge between two faces is thereby brought onto both; a point inside a face is not pulled onto it. The step still goes through the existing quality guard.

Measured (thick cylinder, `tests/high_order_convergence.rs`, release): deepest node outside the body 0.111 to 0.0125 (h = 0.28) and 0.055 to 0.0035 (h = 0.14); Tet10 maximum radial error at h = 0.14 3.5e-3 to 5.0e-4 and rms 4.3e-4 to 1.6e-4; observed rates 0.90 to 2.76 (Tet10) and 1.83 to 2.15 (Tet4) in h over h = 0.4 to 0.14. Tet4 remains unchanged where there was no such vertex. Regression test `a_vertex_on_an_end_plane_is_snapped_to_the_bore_it_lies_just_inside_of` fails on the old code (verified by stashing the fix) and passes now. `cargo test -p fea-core`: 520 passed, 0 failed; `cargo test -p fea-problem`: 205 passed, 0 failed.

Still open (#55): the `refused` count by the 2 % criterion is unchanged (28 / 27 / 62 / 41), so some vertices sit a little off the surface and the Tet10 maximum error at h = 0.20 (9.3e-3, worst nodes 1.4 % inside the bore at mid-height) remains an outlier that this fix does not touch; a clean asymptotic rate in the maximum norm and an exact CAD-parameter projection (rather than the signed-distance projection) are not delivered.

Limits: one body; macOS arm64 only; no Windows or hosted-CI evidence.
