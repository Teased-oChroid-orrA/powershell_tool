# Issue 46 — Phase 9: explicit bounded cylindrical chart canonicalization

Source `8ab1b2be2a64fe9c3b27e19d19480b293b61da59` adds `ChartPolicy::CanonicalizeWithinTolerance`, an explicit alternative to unchanged strict/default chart handling. It uses supported analytic line/circle invariants to canonicalize circumferential/axial parameters. Each changed sample records face, bound, oriented edge use, edge and sample IDs, before/after chart coordinates and surface-projection deviation. Both parameter change and projection deviation must fit the existing immutable model geometry tolerance; ambiguous anchors or work-budget exhaustion refuse the operation. Authoritative world boundary samples and original STEP/model data are unchanged.

Reports travel through chart triangulation, sampled surface, immutable facet check and distance-solid conversion. The tilted cylinder that remains refused in strict mode now passes explicitly canonicalized triangulation, global facet checks and the existing 1e-3 relative analytic volume check at 0.001 mm chord resolution. Tests verify original world samples, unique report references and exact report preservation. This is parameter canonicalization, **not general B-Rep sewing/healing or exact CAD certification**.

A generated 6,132-byte tilted-cylinder STEP regression is committed under `solid-kernel/tests/data/`, with provenance recorded there. It runs without OCCT; independently generated OCCT cases remain in the CAD-enabled suite. The developer diagnostic exposes `--canonical-surface` separately from strict `--surface` and prints report summary and tolerance explicitly.

At the final committed source **54 CAD-enabled tests, 42 feature-off tests and CAD-enabled app lib/tests compilation passed**. Explicit CLI mode succeeds with 22 changed samples, maximum projection deviation **1.407097852748628e-12 mm** against the unchanged **1e-7 mm** tolerance, 59 vertices / 114 triangles / three source faces and 2,275 candidate facet pairs. Strict CLI mode exits 1 with the original single-turn certificate refusal. The default chord is 0.05 mm; the developer CLI reports sampled volume, not exact mass properties. [Verification](issue-46-phase-9-verification.json).

No tolerance increase, implicit fallback, world-coordinate snapping, new dependency, extra hosted CI or production importer/main change. An intermediate report originally identified only edge IDs; oriented use/bound IDs were added because seam occurrences need unambiguous tracing. Next: similarly explicit face-orientation repair with complete reports and geometry gates, then broader native exchange/corpus coverage and PLC recovery. The full epic and OCCT retirement remain open.
