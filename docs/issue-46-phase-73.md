# Issue 46 — Phase 73: reconnect-and-snap-again boundary layer in the signed-distance mesher (#55)

Measurement that started it (Phase 70 addendum): on the signed-distance unit sphere (`sdf = |x| - 1`, linear tetrahedra) the mesher's snapped / refused boundary vertices were 194 / 96 (h = 0.5), 425 / 99 (h = 0.3) and 1658 / 192 (h = 0.2), i.e. 33 %, 19 % and 10 % of the boundary vertices stayed off the surface. Experiments (all recorded in this report): loosening `MIN_QUALITY` / `MAX_QUALITY_LOSS`, raising `SNAP_PASSES` to 20 or the snapping reach to 2.5 local edge lengths changed nothing at h = 0.5; the refused vertices were already within 3-7 % of a local edge length of the surface, belonging to boundary-layer sliver tetrahedra whose quality the snap guards protect.

Change (`fea-core/src/tetmesh.rs`): the snap-and-smooth block now runs in rounds. After a round, if some boundary vertex is still off the surface, the tetrahedra are reconnected with the Phase 65 machinery (`TetTopology` + `tet_smooth::optimize`: exact 2-3 flips / edge removal and interior smoothing; surface faces and boundary vertices never change) and snapping runs again (`RECONNECT_ROUNDS` = 4, early exit when nothing is left). The reconnection is accepted only if the mesher's own worst quality does not fall below `min(before, MIN_QUALITY)`. The reconnection is deliberately cheap (3 flip passes, 2 smoothing passes, 1 round): a heavier setting (50 / 20 / 6) cost 100 times the old meshing time (20 s against 0.2 s for the three meshes in debug) and was not better.

Evidence (macOS arm64, debug): snapped / refused 290 / 0 (h = 0.5, worst quality 0.293), 500 / 24 (h = 0.3, 0.051), 1850 / 0 (h = 0.2, 0.111) against 194 / 96, 425 / 99, 1658 / 192 before. Cost: the three meshes take 2.6 s against 0.2 s in a debug build (about 13x; the tetrahedra counts are unchanged to within 1-2 % because flips can remove edges). New `fea-core/tests/tetmesh_snap.rs`: at most 5 % of boundary vertices stay off the surface for h = 0.5, 0.3, 0.2; the worst quality stays above the 0.05 floor; no inverted element; the enclosed volume is within 10 % of the ball's; the meshing is deterministic. Workspace tests (`cargo test --workspace --locked --offline --no-fail-fast`): 2810 passed, 0 failed, 87 ignored. One `app-tui` Bushing test (`solving_shows_the_fit_pressure_beside_the_closed_form_...`) timed out once under the full parallel debug run (90 s limit) and passes alone in 9 s; it does not use the tet mesher.

**Two defects found and fixed on the way.** (1) The reconnection replaces the tetrahedra behind boundary faces, but the mesher oriented each named surface face with a stored interior-side vertex from before it: about half of the thick-cylinder bore faces ended up facing into the solid, the internal pressure changed sign there and the Lamé check read a 107 % error at h = 0.1 (found by the existing `tetmesh` test). Named faces are now oriented by construction (a face taken from a positively oriented tetrahedron is already outward; deciding it by a dot product with the fourth vertex is ill-conditioned for sliver triangles lying on the surface) and the interior-side vertices are refreshed after the snap rounds; the Lamé error at h = 0.1 is now 9.5e-4 (2.3e-3 before this phase). (2) Measured, not fixed: 36 of 1044 sphere faces at h = 0.3 face the axis in the old mesher as well as the new one (0 at h = 0.5 and 0.2): cap-sliver tetrahedra allowed by the 0.05 quality floor; `tests/tetmesh_snap.rs` bounds the fraction at 5 %.

Limits (not fixed): h = 0.3 still leaves 24 vertices (4.6 %) off the surface; the mesher is about 13x slower in debug (the release factor was not measured) so a caller that meshes in a loop should count that; reconnection only improves what snapping allows, so exact CAD-parameter projection with a validity guard, a high-order convergence study and its cost remain open for #55; the Tet10 curved edges are unchanged; no Windows or hosted-CI evidence.
