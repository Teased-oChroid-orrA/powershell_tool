# Issue 46 — Phase 98: the stored adapted mesh as the starting-mesh recommendation (#62)

Phases 80-97 showed that zone multipliers and size fields cannot shorten an adaptive run, and that the only start that does is the adapted mesh itself. `adaptivity::MeshStore` makes that the recommendation: `remember(key, &AmrResult)` keeps the final mesh of a run that ended `Converged` under its `WorkloadKey` (exact equality, a later run of the key replaces the earlier one, non-converged runs are refused), `recall(&key)` returns it or nothing (never a similar class). The recalled mesh is a *starting* mesh only: the caller builds its problem on it (loads and supports may differ) and `run_amr` still solves, estimates and either accepts it or continues refining.

Evidence (`tests/amr_advice_classes.rs::a_stored_adapted_mesh_starts_the_next_run_of_the_same_class_at_about_half_the_time`, macOS arm64, release): the plate with a hole is run to a relative goal tolerance of 1e-4 and remembered; the same plate under a 1.5 times larger traction (the linear goal and its tolerance scale with it) is run twice, from the coarse default start and from the recalled mesh: **4 cycles, 7588 dofs, 0.75 s against 1 cycle, 7588 dofs, 0.42 s: time ratio 0.56**, both ending `Converged`. A different class finds nothing in the store; a run that did not converge is not remembered. This meets the #62 criterion "improved initial mesh recommendations reduce time-to-accuracy" on the measured class, with the ceiling of Phase 93 (0.49-0.61x) as its bound.

Limits: in memory only (persistence and its integrity rules belong to `fea-problem`, whose verified telemetry store is the model, and what to keep on disk is a product decision); one geometry class and one load change measured (the plate with a hole; the earlier L-plate and Lame classes are meshes where the default already needs one or two cycles); the geometry key is the caller's canonical descriptor, so a stale mesh for changed geometry is prevented only by that descriptor changing; a mesh stored for a looser tolerance is refined further by the controller, which is the point of keeping it a start; macOS arm64 only.
