# Issue 46: native tilted-hole quality plan

Status: research and execution plan, 2026-10-23. No chart rule, solver gate, or retirement flag changes here.

## Objective and current evidence

Make the native tessellation of `solid-kernel/tests/data/tilted-hole.step` produce a volume mesh that passes `QualityThresholds::default()` and completes the existing static benchmark solve, without restoring the known curved-chord overlap with a neighboring face. The same STEP text and element size must be compared with OCCT. Phase 131 measured one native boundary tet at scaled Jacobian 0.064734615306 (gate 0.1), while OCCT's minimum was about 0.121. Both paths solved with equilibrium near 1e-12; the diagnostic `table` exited zero despite the native quality failure.

The traced bad tet touched `face3` (plane) and `face7` (cylinder). Its nearby source cylinder triangle descended from an interior boundary-to-boundary diagonal between bottom-rim edge #399 sample 4 and top-rim edge #265 sample 12, followed by repeated refinements toward the top rim. Disabling *all* such cylindrical refinement cleared this particular gate, but Phase 130 showed that the rule exists to avoid a shallow cylindrical chord overlapping an adjacent plane. Two narrower Phase 131 rules removed a few chart points and did not change the failure. Those experiments were reverted; the trace is causal evidence for investigation, not proof that skipping the single seed is safe or sufficient.

## Research and design boundary

[CGAL's MeshDomainWithFeatures_3 contract](https://doc.cgal.org/latest/Mesh_3/classMeshDomainWithFeatures__3.html) treats surfaces, intersection curves and corners as distinct geometric entities. Its [polyhedral domain reference](https://doc.cgal.org/latest/Mesh_3/classCGAL_1_1Polyhedral__mesh__domain__with__features__3.html) explicitly requires intersection testing at the boundary, and its [polygon intersection documentation](https://doc.cgal.org/latest/Polygon_mesh_processing/) distinguishes legitimate shared edges from face intersections. This supports checking the *trimmed neighboring face domain* of any proposed chord skip, rather than inferring safety from an axial coordinate or the two endpoints. These are design references, not an instruction to add CGAL or copy its code.

The responsible local path is `AnalyticModel::triangulate_sampled_chart_with_quality` -> `chart_mesh::triangulate` -> `shape_chart` (`solid-kernel/src/chart_mesh.rs`). `shape_chart` sees only its own face loops and surface; its current curved interior chord rule splits boundary-to-boundary diagonals. `fea-problem::native_solid::tessellate_step_native` then creates the tagged surface, and both OCCT/native comparisons pass through `solid_kernel::mesh_volume` and the same `fea-core` volume mesher. A cross-face certificate belongs at the analytic-model/face-input boundary and should be passed to the chart rule only if the focused evidence demonstrates a safe, small interface. Do not change the volume mesher to mask a chart defect.

## Execution tasks and gates

1. **Reproduce on unchanged source.** Inspect git status and CodeGraph freshness; preserve unrelated untracked files. Run the release `CASE='tilted hole'` comparison and capture both rows, including quality, elements/DOFs, named surfaces, load reaction, equilibrium and timings. Use temporary diagnostics only to connect the exact seed diagonal to the generated surface triangles and bad tet; restore diagnostic code. Record the current source hash and note that `table` prints rather than asserts the gate.
2. **Build two permanent synthetic regressions first.** In `solid-kernel/tests` near chart/curved STEP tests, construct a shallow cylindrical patch whose unsplit interior 3D chord intersects the *material* of an adjacent trimmed planar face; assert the split prevents surface overlap and preserves a closed, outward, tagged shell. Construct an otherwise similar tilted cylinder with a planar opening through which the candidate chord passes; assert the safe case does not over-refine, and a noncoplanar/oblique neighboring face still triggers the overlap guard. Include boundary/tangent contact and a face with a hole; use the existing intersection and trim-classification machinery if it can certify the full segment. An uncertain intersection must retain refinement or refuse explicitly, never be treated as safe by a midpoint-only or endpoint-only test.
3. **Isolate and repair the actual seed.** For the Phase 131 edge #399[4] to #265[12], measure whether its straight chord intersects any adjacent trimmed face or the sampled shell away from shared endpoints. First test selective suppression on that seed only, with the synthetic overlap cases active, then run the tilted-hole release mesh gate. If it fails, restore the trial and trace the next ancestry; do not generalize a failed rule. If suppression is unsafe, keep the chord split and instead test a bounded local chart retriangulation or insertion ordering that removes the bad SDF perturbation while preserving boundary constraints and chord tolerance. Preserve `shape_chart`'s work budget and determinism.
4. **Validate the complete surface.** Require no nonincident triangle intersections, orientation inversion, duplicate or missing boundary segments, face-name drift, or widened CAD deviation on the tilted-hole fixture and synthetic cases. Check the cylinder chart's area/triangle count and shell volume against the baseline; an improvement in the one tet does not excuse a new surface mismatch. Run `cargo test -p solid-kernel --no-default-features --locked --offline -j1`, and the relevant chart, STEP, and surface tests with OCCT where available.
5. **Require the focused same-STEP mesh and solve.** Run `CASE='tilted hole' rtk bypass cargo test -p fea-problem --features occt --release --locked --offline -j1 --test occt_vs_native -- --ignored --nocapture table` with `NO_SOLVE` unset. Explicitly check `q.acceptable(&QualityThresholds::default())` and zero sub-gate tets on native, successful static solve, equilibrium within the existing benchmark threshold, unchanged supports/load face, and comparative minimum scaled Jacobian, radius/edge ratios, size jump, elements/DOFs, displacement, energy, reaction and time. A zero process exit from `table` alone is insufficient. Add an asserted focused regression at the existing test layer if practical. Do not relax the existing quality or parity tolerances.
6. **Check blast radius and integrate.** Re-run the existing asserted OCCT/native comparison and, if the shared chart rule changed, the full 19-model release table with actual solves; identify every residual failing model separately. Run `cargo test -p fea-problem --features occt --locked --offline -j1` and `cargo check -p app-tui --features occt --lib --tests --locked --offline -j1` for the touched production path. Serialize Cargo, watch disk, use this checkout's target, re-query CodeGraph callers, and capture exact command outcomes and limits in a new append-only phase note. Advance the live pointer/checklist only to evidenced scope, using the authorized forward-only branch/PR/merge flow. OCCT remains production and `occt_retirement_approved` remains false pending separate owner approval.

## Reject or redesign

Reject a candidate if it clears the tilted-hole tet by allowing a chord through an oblique or trimmed neighboring face, loosening a tolerance, moving a surface point off its CAD face, or regressing another model's surface/solver gate. Record the counterexample and resume from the cross-face or volume-boundary diagnosis rather than retaining a partial guard.
