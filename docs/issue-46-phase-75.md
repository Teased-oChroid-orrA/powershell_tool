# Issue 46 — Phase 75: AMR feedback for the strategy autotuner (#62)

New `fea_core::adaptivity::feedback` implements the consuming side of the autotuning addendum's section 60 / Phase E, with its boundaries built in:

- `summarize(key, &AmrResult) -> RunSummary`: cycles, how the run ended, dof growth, initial and final physics error, geometric-mean error reduction per cycle, total stage seconds, and the **regional refinement demand** per zone (the sum over cycles of the fraction of the zone's elements that were marked: about the number of refinements an element of the zone went through). Regional detail needs the run to have kept every cycle's fields (`FieldRetention::All`); otherwise `has_regional_detail` is false and the run is not usable.
- `WorkloadKey` (geometry, material, boundary conditions, contact, quantities of interest) identifies a class by exact equality: histories of a different key are never pooled, so a mesh is never inferred accurate for a merely similar problem.
- `advise(history, key, options) -> Option<Advice>`: uses only runs of exactly that key that **converged** and have regional detail; fewer than `min_runs` (3) validated runs give `None` and the deterministic default start applies. For each zone with enough runs and a coefficient of variation of its demand at most `max_cv` (0.5) it advises an **initial size multiplier** `refine_ratio^(depth_fraction * mean demand)` clamped to `[min_scale, 1]` (defaults 0.5, 0.5, 0.25), plus the expected cycles, dof growth and seconds of the class. Multipliers can only be `<= 1`: the advice asks for a finer start, never suppresses a refinement, and `run_amr` is untouched, so AMR remains the authority and every advised mesh goes through the normal AMR checks.

Evidence (macOS arm64): 4 unit tests (consistent runs advise ~0.5 for a zone with demand ~2 and ~0.97 for a barely refined zone; unconverged, detail-less and other-key runs are ignored and two validated runs are too few; disagreeing runs give no advice for that zone; extreme demand is floored at 0.25) and 3 integration tests on a real adaptive run of the L-shaped plate: the summary reports 3 cycles, dof growth 3.30, physics error 0.160 to 0.070 (0.664 per cycle) and a demand of 0.42 in the `Singular` (re-entrant corner) zone against 0 elsewhere; three repeats give an advice of `Singular` 0.864 (expected 3 cycles, 3.3x dofs); one run, or another key, gives none. `cargo test -p fea-core`: see the PR.

**Exit gate not met (measured).** Starting the plate with the advised size (0.4 x 0.864 within 0.35 of the corner) gives exactly the same result as the default start: 3 cycles, 892 dofs, physics error 7.049e-2, 0.17 s in both. The advice is correct as a statement of where AMR spent its effort, but on this benchmark it changes nothing, so "improved initial mesh recommendations reduce time-to-accuracy on representative benchmark classes" is not shown, and #62 stays open.

Limits (not fixed): no representative benchmark classes exist, so time-to-accuracy has not been demonstrated; the advice maps to zone names, and turning a zone multiplier into a spatial size function is the caller's job (the experiment above used a disc around the known corner); demand is the marked fraction, not a calibrated predictor of the final size; goal-specific and contact-zone refinement frequencies and anisotropy effectiveness are not summarised; the summaries are in memory (persistence belongs to the verified telemetry store); no Windows or hosted-CI evidence.
