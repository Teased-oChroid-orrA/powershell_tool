PR #75 merged at `8459f02`, old branch deleted. Continuation: `feature/native-cad-spline-parameter-bounds`. Feature source `b6093e4`; qualified source includes the boundary fix below.

`SplineParameterMap` binds a source face/spline surface/body unit context through the same authoritative `BodyContext::spline_surface_source` helper used by the existing physical surface reader. It decodes Cartesian controls with an identity factor, retains their accepted binary64 source coordinates in the evaluator, encloses raw UV with the shared rational tensor recurrence, then scales world bounds outward to millimetres. This includes source-to-world conversion rounding. UV and knots never receive the body length factor. Raw control arithmetic must satisfy the evaluator's explicit supported range; unsupported raw coordinates refuse even if another normalization might be representable.

Shared raw parameter-curve bounds support LINE, CIRCLE and rational spline intervals. Original source direction ratios are used, not rounded display normalizations. CIRCLE parameter angles use the existing certified [-8,8] radian Taylor enclosure. Curve-span and surface-patch/blend limits remain independent hard budgets. The resulting UV rectangle must lie within the finite surface domain; there is no implicit wrap, clamp or renormalization. Loose boxes can conservatively refuse and be subdivided by the caller. No general projection uniqueness, regularity, source 3D-locus agreement, trim/master/body validity or full spline import is inferred.

Generated rational quarter-cylinder declarations exercise complete-interval line/circle/spline composition, independent analytic point containment, metre conversion without rescaled UV/knots, stale references, wrong basis, out-of-domain input and both work budgets. The altered face/new p-curves are declaration/binding fixtures, **not** claimed coherent edited solids.

## Reproduced boundary defect and correction

A new exact-boundary test failed at the original source: a unit-axis parameter line on UV [0,1] was padded just outside the surface domain by generic outward zero/unit operations. The surface correctly refused the out-of-domain box. The correction preserves only provably exact finite operations: zero/unit multiplication/division, equal or negated point quotients, zero/cancelling/equal-operand sums (finite binary doubling is exact), and square/square-root at exact zero/unit values. Other products/quotients/sums still round outward, with product sign bounds. Four endpoint combinations remain authoritative for interval multiplication/division. No UV interval is clipped, no coordinate changed, and no tolerance/domain/budget relaxed.

The regression now passes forward/reversed boundary lines and a boundary-touching circle. Existing rounding, underflow and zero-denominator tests retain their assertions; general sampling, projection and enclosure tests pass. An unused test import was removed.
