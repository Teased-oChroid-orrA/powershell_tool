# Phase 152: fillet snap and seam evaluation

Issue #63, excluding NEMA17 by owner request. This is a bounded negative result: no mesher change was retained. OCCT remains the comparison surface provider; both OCCT and native surfaces use the same volume mesher. `occt_retirement_approved` stays false.

## Reproduced mechanisms

The OpenCascade-enabled `fillet_rim_tagging` regression has two distinct failures. At size 1 mm the top face carries 80.42372283704826 mm² against an exact 80 mm² and a 0.5% limit. Phase 150 traced this to boundary triangles crossing the flat/fillet seam and whole-triangle face ownership. At size 0.85 mm a boundary node lies outside the solid: `[7.499999999999975, 14.02618438364114, 14.002578936690856]`, beyond the box plus the test's 0.0255 mm allowance. The same node and signed surface distance +0.026311 mm are present before boundary repair.

The input tessellation is bounded exactly by `[0,0,0]` and `[12,14,16]`, with zero vertices outside. The lattice node starts at `[7.5,14,14.4]`, signed distance +0.039664 mm. Its two active face hits are the flat face 0.4 mm away and the curved face 0.039664 mm away. `snap_to_features` pulls it toward their seam to `[7.5,14.037332,14.003677]`, still +0.037513 mm off the surface; the plain signed-distance projection instead lands on the curved patch at `[7.5,13.961570,14.390182]`. The alternating feature projection does not converge within its 12 iterations, but its residual is below the caller's `0.05 * local_size` allowance. Subsequent passes reduce the residual slowly; a quality-guarded partial move leaves the failing node. This is a shared volume-mesher behavior, not an OCCT vertex outside the box.

## Candidates evaluated and rejected

1. Post-repair projection of two-face vertices onto the shared seam, with face-owner, cell-quality, local-volume and scaled-Jacobian guards: the 0.85 mm test still failed at a different node, `[6.75,14.033822,14.031456]`.
2. Direct projection when active faces report the same nearest point: the 0.85 mm test still failed at `[8.25,14.033171,14.040767]`.
3. Refusing a feature target that increases positive signed distance: the original 0.85 mm node still failed. Its first feature target slightly *decreases* distance while moving outside the model box.
4. If alternating projection remains farther than its surface accuracy `eps`, use the nearest trimmed-face foot: the 0.85 mm OCCT test passed and the native fillet test, `high_order_convergence` and `tetmesh_repair` passed (6 tests, 4 ignored). The 1 mm OCCT face area remained 80.421866 mm², beyond the 80.4 limit. More importantly, the 18-model, 36-row mesh-only parity table (NEMA17 excluded) lost a passing gate: native `cross-bore, filleted` went from 0 to 2 tetrahedra under scaled Jacobian 0.1, with minimum 0.043 instead of 0.120. The table command exited successfully because it prints diagnostics and has no gate assertion; the candidate is a regression.
5. Restricting that fallback to two faces with nearly parallel intrinsic surface normals did not isolate the fillet: native `cross-bore, filleted` still had 2 sub-gate tetrahedra, minimum 0.073. The other focused filleted cases kept their gates. This candidate was also removed.

All candidate switches, diagnostic prints and 0.85-only/non-NEMA test filters were removed. The existing assertions and production code remain unchanged.

The focused runs used the worktree's own Cargo target, `--release --locked --offline -j1`, and the local OCCT 8.0.1 bundle. Commands were `cargo test -p fea-problem --features occt --test fillet_rim_tagging the_flat_face_next_to_tangent_fillets -- --nocapture`, the same test with `--no-default-features` for the native path, `cargo test -p fea-core --no-default-features --test high_order_convergence --test tetmesh_repair`, and `NO_SOLVE=1 cargo test -p fea-problem --features occt --test occt_vs_native table -- --ignored --nocapture`. The parity run temporarily omitted NEMA17. `NO_SOLVE=1` means these rows establish mesh quality only, not solver equivalence. The experimental logs are under `/private/tmp/issue46-phase152-{parity,filleted}.log` and are not checked-in evidence artifacts.

## Next design gate

For the 0.85 mm out-of-box node, a defensible fix must choose the curved face rather than the distant flat face *before* the vertex is pulled toward the seam. A promising discriminator is the ratio between the nearest and other trimmed-face distances (0.0397 versus 0.4 mm here), but it must be measured on the passing sharp-feature and reentrant cases before changing active-face selection. A fixed ratio without that evidence risks repeating the cross-bore regression. A small synthetic pair of trimmed tangent patches should assert feature ownership, surface distance, and no lost sharp edge before another full parity run.

The 1 mm loaded-area error needs a separate seam-conforming boundary topology: find the seam crossing on each boundary edge, split adjacent tetrahedra conformingly, and tag only triangles wholly on one face. Relabeling, clamping vertices to a box, or increasing the area tolerance would hide the physical load error. The existing `boundary_repair::split_edge` does not locate CAD seams and can refuse pinned feature edges. Evaluate a surface-constrained volume route as an alternative to repairing the lattice boundary, but require unchanged default quality gates, positive and conforming cells, exact face ownership, bounded work, and native/OCCT solve agreement before replacing the current route. The ABC small-angle and chart-refusal gates and Windows native-only mesh/solve evidence remain separate prerequisites to OCCT retirement.
