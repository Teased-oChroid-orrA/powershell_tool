# Issue 46 — Phase 87: sliding nodes, the motion + remesh + transfer loop and a hidden-inversion defect (#59)

Three additions to the mesh-motion subsystem (Phase 72) and one defect found while building them.

**Sliding nodes.** `meshing::motion::Slide { node, axis, displacement }` fixes one coordinate of a node's displacement and leaves the others to the interior solve (symmetry planes, frictionless walls, flat boundaries that must stay flat); `move_mesh_sliding(mesh, prescribed, slides, options)` takes both, `move_mesh` is the same call with no slides. Axis-aligned only (a general plane or a curved boundary still needs the caller's projected target as a full `Prescribed`). A 4x4x4 box compressed to 40 % of its height with sliding walls keeps a minimum scaled Jacobian of **1.000**; the same compression with all wall nodes pinned laterally gives **0.385**.

**The loop.** `adaptivity::moving::advance(mesh, field, constraints, remesh, options)` moves the body to the target the caller's `constraints(&mesh)` describes (positions, so the remaining displacement is recomputed on whatever mesh is current); on `Outcome::NeedsRemesh` it calls the caller's remesher, carries the nodal field to the new mesh with `NodalInterpolation` (an unlocated node beyond the tolerated fraction is an error, never a silent zero), asks for the constraints of the new mesh and continues, within `max_remeshes`. A remesh that yields no progress ends in an error naming the reason, a spent budget returns the last valid mesh with `complete = false`, a failing remesher's error and a wrong-length field are passed on or refused. Test: a unit box on 3 layers is compressed to 3 % of its height (edge-ratio ceiling 30): the motion hands over at 96.6 % of the way, the body is regridded to one layer (64 to 32 nodes, 0 unlocated), the second segment completes, the top is at 0.03 and the carried material position matches the node to **2e-14** (the uniaxial motion is affine, so the transfer is exact) with the edge ratio at 25.5.

**Defect found and fixed (`move_mesh`).** The step quality gate measured corner and centroid Jacobians (`Mesh::quality`), but a warped `Hex8` can be negative between them; the next pseudo-elastic solve then refused the mesh with an error (`inverted or degenerate element (Jacobian -1.0e-6 at Gauss point 4)`) instead of rolling back and handing over. A 4x4x4 box twisted by 200 degrees showed it. The gate now also checks the Jacobian at every Gauss point (the assembly's own `kernel::geometry` test), so such a step is rolled back and the motion ends in `NeedsRemesh` or completes. Test: twists of 200, 450 and 720 degrees all return a mesh with no inverted element and no error (450 and 720 hand over, as expected).

Evidence (macOS arm64): 4 new tests in `adaptivity::moving`, 1 in `meshing::motion`; `cargo test -p fea-core`: 528 passed, 0 failed.

Limits (not fixed): the remesher is the caller's (the test regrids a box; an r-adaptive Laplacian smoothing of the twisted box produced inverted elements and is not a remesher for large twists); sliding is axis-aligned; the transfer is nodal interpolation (history variables and conservative transfer are not covered, plasticity history still uses `transfer_history`); no ALE (no mesh velocity, no convective terms); no Windows or hosted-CI evidence. #59 stays open for ALE and conservative transfer.
