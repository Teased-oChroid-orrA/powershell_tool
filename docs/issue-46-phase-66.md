# Issue 46 — Phase 66: planar boundary sliding for tetrahedral smoothing (#53)

Extends Phase 65 (`meshing::tet_smooth`). New `SmoothOptions::slide_planar_boundary` (default `false`, so boundary vertices stay bit-identical unless asked) lets a boundary vertex move inside its plane when all of its boundary faces are coplanar (unit normals agree to 1 - |dot| < 1e-9). The step is the usual neighbour average projected onto the plane, guarded exactly as before (exact orientation of every incident tetrahedron unchanged, worst incident radius ratio must improve). Vertices on a surface edge or corner (faces in more than one plane), non-planar boundary vertices and protected vertices never move; connectivity and the boundary face set are unchanged and the volume is re-checked.

Evidence (macOS arm64, debug; 8 corners + 60 interior + 6 points on each cube face, seeds 1-6; worst radius ratio after smoothing): interior-only 0.0227 / 0.0313 / 0.0166 / 0.0083 / 0.0086 / 0.0079 versus with planar sliding 0.0355 / 0.0433 / 0.0707 / 0.0083 / 0.0240 / 0.0192 (119-134 boundary vertices slid per cloud). Cube corner and edge vertices are asserted unmoved, every slid vertex keeps its exact face coordinate, the boundary face set and the volume (1 to 1e-12) are unchanged. Full `fea-core` suite: 482 passed, 0 failed across all test binaries; clippy clean for the file.

Limits (not fixed): seed 4 gains nothing (its worst cell is attached to edge or corner vertices, which cannot move); curved boundaries (a sphere, the NEMA17 shell) are not handled, because only exactly planar patches slide; there is no edge-sliding, Steiner insertion or sliver exudation; not wired into production (OCCT stays production); no Windows or hosted-CI evidence.
