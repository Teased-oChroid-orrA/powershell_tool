# Issue 46 — Phase 10: explicit whole-face orientation repair

Source `3b55ed5614b601687a73d184ed490bc0de53981d` adds opt-in `OrientationPolicy::RepairWithReport`; strict remains the default. Exact edge-direction parity propagates across a closed sampled shell. The operation refuses nonorientability, open/nonmanifold edges, disconnected shells and any repair requiring different flips within one source face. Compensated translated signed volume chooses the outward global orientation. Every changed source face records its ID and before/after `same_sense` flag. Coordinates, topology, original analytic model and STEP bytes remain unchanged.

Repair commits triangle winding only after all constraints and cancellation checks pass. Progress identifies triangulation, orientation work and completion. Existing closed-edge/cyclic-vertex-link validation and subsequent global sampled intersection checks remain required. This is conservative sampled whole-face orientation repair, not exact B-Rep sewing or general CAD healing. CLI `--repair-orientation` explicitly requests it and can combine with `--canonical-surface`; both default policies stay strict.

The real bracket regression deliberately reverses one source ADVANCED_FACE flag. Strict generation refuses it; explicit repair restores the original mesh exactly, reports that face, leaves the source model unchanged and preserves the report through intersection checking and distance-solid conversion. Unit regressions cover all-face reversal, mixed-source-face flips, cancellation, nonmanifold incidence and a nonorientable projective-plane triangulation. Negative operations preserve the input mesh.

`NativeDistanceSolid::into_parts` now returns `(SurfaceSolid, NativeGeometryMetadata)`, keeping source-face IDs and both report types together. Existing read-only getters remain available. No repository consumer used the earlier draft tuple interface.
