# Issue 46 — Phase 74: the full total-cost objective, memory/time limits and break-even analysis (#60)

`fea_core::meshing::cost` implemented part of the epic's objective `C_total = C_CAD + C_mesh + C_assembly + C_solve + C_error + C_adapt + C_transfer`: the CAD and transfer terms were missing, every term was charged once per mesh whatever the number of analyses, and a candidate could not be bounded by memory or time. Now:

- `Workload` gains `cad_seconds`, `transfer_seconds` and `analyses` (default 1). `CostModel::predict` = `one_time_seconds` (CAD + generation + estimation + adaptation + transfer, paid once per mesh) + `per_analysis_seconds` (assembly, factorisation, back-substitution from the calibrated rates) x `analyses`. For a single analysis with the new terms at zero the prediction is exactly the old one (test).
- `MeshCost::memory_bytes` estimates the peak of a direct solve (factor + stiffness + eight vectors per dof, 8-byte scalars).
- `choose_within(candidates, model, workload, allow_unvalidated, Limits { max_memory_bytes, max_seconds })` excludes candidates over a limit (the baseline included), lists every exclusion with its reason in `Choice::rejected`, and returns an error naming the limits when nothing is feasible, never a silently infeasible pick. `choose` is `choose_within` with no limits.
- `break_even_analyses(a, b, model, workload)` is the number of analyses after which candidate `b` (dearer to make, cheaper to solve) overtakes `a`, or `None` when it never does or already wins for one analysis. This is the reuse-aware part of the epic's "for repeated solves, account for reuse and the number of analysis runs".

Evidence (macOS arm64): 3 new tests plus the existing ones (`cargo test -p fea-core`: 499 passed, 0 failed). One-time terms: 10 + 7 + 2 + 5 + 3 = 27 s exact, the solver terms scale with the analyses and the legacy prediction is unchanged. For two meshes (20x20 and 8x8 Quad4) where the small one costs 50 s more to make, `choose` picks the big one at 0.9 x break-even and the small one at 1.1 x break-even. A memory limit between the two estimates keeps the small mesh and reports the big one as rejected for memory; a limit below both, or a zero time limit, is an error; no limits equals `choose`.

Limits (not fixed): the rates are the existing calibration (a direct solver on one machine; the `predictions_track_measured_solve_times` timing test stays `#[ignore]`d); the memory figure is an estimate for ranking against a budget; the cost of an iterative or AMG solve, of contact/plasticity iterations beyond the caller's counts, and learned corrections are not modelled; no representative verified benchmark set exists yet, so nothing here proves accuracy (a candidate that `NeedsValidation` still needs an error estimate); no Windows or hosted-CI evidence.
