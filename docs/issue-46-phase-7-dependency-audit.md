# Issue 46 — Phase 7 dependency decision: spade for 2D charts

`spade` **2.15.1** is pinned exactly for boundary-preserving constrained Delaunay triangulation of native analytic face charts. Registry artifact checksum: `9699399fd9349b00b184f5635b074f9ec93afffef30c853f8c875b32c0f8c7fa`. Source: <https://github.com/Stoeoef/spade>. Its crate manifest and source were inspected locally before integration; it is Rust 2021, has no build script/native CAD library, and offers MIT OR Apache-2.0 licensing. This distribution elects MIT and ships the exact upstream notice at `licenses/spade-LICENSE-MIT.txt` (SHA-256 `fc1a4c9482e823f450af4c85471ca6e58d1fd0b3bd0998be4547b1be4a5bc4af`). The release workflow already copies all license files.

The existing `fea-core::delaunay` quality mesher conformingly splits encroached boundary subsegments. Independent face calls would therefore change shared CAD edge discretizations unless a global resampling protocol were supplied. The new diagnostic path instead needs fixed, already shared boundary segments. Spade supplies incremental constraint recovery with robust predicates; the wrapper checks every segment's incidence and input identity, explicitly refuses conflicting/unresolved coordinates, and does not invoke constraint-splitting APIs. Existing quality/volume meshers remain authoritative for their current application workflows.

The only new locked package is spade. Its dependencies (`hashbrown` 0.16.1, `num-traits`, `robust`, `smallvec`) were already in the application lockfile; no existing versions are upgraded. Feature unification does rebuild some shared numerical/CAD dependencies locally. The application lockfile retains unrelated Windows dependency selections; incidental resolver updates were removed before locked verification. Production compilation and numerical consumers still require their regression checks.

This is a **2D CDT dependency decision**, not selection of a full native CAD kernel, qualification of Truck or constrained 3D meshing. No runtime network access is introduced. OCCT remains optional and retained; its licensing/release obligations are unchanged. All existing source capability, geometric validity, quality, platform and final retirement gates still apply.
