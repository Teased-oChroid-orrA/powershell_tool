Moving the last four terminal workbenches into native windows

Pressure Vessel, Lug Analysis, Preload Analysis and Material Lookup still open in a console from the dashboard. This proposes how each one looks and works as a native window, and which existing code each port reuses. Nothing below is built yet except the console fix.

Console window fix: done, compiles, awaiting Windows CI 4 window ports: awaiting your approval
Already fixed

The blank console beside the dashboard

Cause

app-tui.exe is a console program, because the terminal toolboxes need a console. Windows gives a double-clicked console program its own console window, and that window stayed open, blank, for as long as the dashboard ran.

Fix (new app-tui/src/console.rs)

  • The dashboard, every native workbench and the result viewer let go of a console that only they use (GetConsoleProcessList == 1, then FreeConsole). A console shared with a shell you typed app-tui --gui into is kept.
  • Windows the dashboard or the FEA hand-off start are created with CREATE_NO_WINDOW, so they don't pop a console of their own. Terminal toolboxes still get a real console through cmd /C start.
  • No new dependency: two kernel32 calls. The rest of the exe stays a console program, so --tui and --toolbox work as before.

Limit: this can only be checked on Windows. A console may flash for a moment at start-up. Removing that flash would mean switching the exe to the GUI subsystem, which breaks the terminal toolboxes.

The proposal

The four windows

Each window uses the same frame as the Fastener Hole and Bushing windows: a step strip, a tree on the left, inspector cards on the right, and a drawing of the part in the middle. Material Lookup has no part to draw, so it is a page like Search. Example values are illustrative, taken from each toolbox's defaults.

Common rules

One model, two heads

  • No formula, row or label is written again in the window. Each window wraps the terminal toolbox's own state, the same way the Fastener, Bushing and Search windows do.
  • The dashboard tiles switch from Opens::Terminal to Opens::Window. New flags: --gpu-pressure-vessel, --gpu-lug, --gpu-preload, --gpu-materials.
  • Every toolbox item the window needs and cannot reach becomes pub(crate), and its callers are checked.

Proof for each port

  • Session tests: edit, undo, save, reopen, results equal the terminal model's for the same inputs.
  • Window input tests through real clicks and keys (window.rs), plus a GPU snapshot in both themes that I look at before calling it done.
  • cargo test -p app-tui and the dashboard test that checks every tile opens the right way.
Your call

3 · Order of work

  1. Material Lookup: smallest, and proves the page bench outside Search.
  2. Pressure Vessel: extracts the shared revolved-drawing module from Fastener Hole.
  3. Preload Analysis: the joint section is drawn from the axisymmetric FE result on fea-core (member stress contour and the compressed zone it finds), with the solver's double frustum (head and nut cones meeting at the stack mid-plane) overlaid for comparison.
  4. Lug Analysis: largest, needs the worker and the exposed fields.

Each one lands as its own commit with its tests, so you can try each window as soon as it is done.
