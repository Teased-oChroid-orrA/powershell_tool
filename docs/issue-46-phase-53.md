# Issue 46 — Phase 53: finite source p-curve endpoint correspondence

PR #80 merged at `72a021e`; tracking-only main `9cdefdc` is the base of `feature/native-cad-pcurve-endpoints`.

`step_pcurve_endpoints::verify` checks a caller-selected nonempty increasing p-curve interval and explicit proposed order against the actual source topological start/end vertices. It reuses the shared plane/cylinder/spline maps, exact-document face/edge/wrapper association and interval Euclidean distance helper. Order is independent of EDGE_CURVE.same_sense; closed coincident endpoints cannot establish winding. Source vertex length conversion is outward rounded before comparison, so the error upper bound includes physical source conversion rather than comparing only rounded display points.

Whole-interval mapping checks finite domain admission, followed by the two endpoint maps. A hard map-enclosure budget (default three), per-enclosure curve-span/surface-patch limits and pre-allocation spline declaration limits are independent. The association helper now accepts explicit limits, with the existing entry point delegating to its unchanged defaults. Progress counts completed enclosures/endpoints; initial, intermediate and final cancellation are atomic. Actual source wrapper/master declarations are reported without semantic master certification.

Targeted evidence: all 176 actual bracket plane-line/cylinder-generator associations (148/28) pass with independently proposed finite parameters and unchanged 1e-7 mm tolerance. Incorrect trims/order, invalid intervals, stale references, all sub-three enclosure caps and initial/final cancellation refuse. Local spline-surface fixtures check all three curve classes, both proposed orders and source mm/metre contexts with unchanged raw parameters. Curve control/span and surface patch caps refuse. These fixtures deliberately change only local endpoint/association contracts; the unchanged underlying 3D master is not certified. This explicitly demonstrates why endpoint success cannot be promoted to full locus/master/body validity.

No development failures or tolerance relaxation. [Frozen-source qualification](issue-46-phase-53-verification.json) at `de5ceed`: 185 CAD-enabled / 168 feature-off tests, zero failures/ignored/warnings; app CAD library/tests compilation passes. OCCT remains production; no dependency or hosted CI. Next: shared whole-trace sampling/locus agreement and finite trim/master/body gates, general constrained meshing/quality and later priorities.

Read-only root spline endpoint probe: 5/15 planar spline p-curves agree with both source vertices at full active-domain endpoints; ten correctly refuse that proposed interval. Refused edge/p-curve pairs: 226/235, 287/294, 350/359, 411/418, 627/636, 711/718, 1263/1272, 1342/1349, 1874/1888, 2872/2886. All ten source edges have distinct start/end vertices, while the underlying p-curve circle trace is closed. This is expected finite-trim admission evidence, not an invalid-source-file finding or a failed test. Their whole underlying trace agreement from earlier phases cannot stand in for finite edge trims. Next work must discover/check appropriate endpoint parameters and choose the correct oriented finite arc, refusing unresolved/wrapping ambiguity.

Read-only follow-on search probe: bounded world-trace distance at objective gap 1e-9 mm found distinct candidate parameters for all ten open spline edges; all ten proposed sorted intervals then passed the endpoint checker at unchanged 1e-7 mm. The remaining five had coincident candidates and were not converted to empty intervals. Across the 30 endpoint searches: 9752 enclosures, one unoptimized concurrent-build wall observation ~0.016 s (pilot only, not representative performance). Maximum observed checked endpoint upper error was below 1e-9 mm. Parameter uniqueness, correct oriented arc and wrap selection remain unproved. This supplies the next regression target; it is not a production trim-discovery implementation.
